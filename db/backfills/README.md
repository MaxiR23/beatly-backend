# db/backfills

SQL data backfills, generated by a script under `scripts/`. Files here
have no number. Unlike `db/migrations/`, which is applied history and
never edited, a file in this directory is regenerated on purpose: if its
generator or its `N` changes, the `.sql` file is regenerated and
versioned together with that change, and a test under `test/scripts/`
fails if the versioned file does not match what the generator produces.
Files here are also re-applied to Supabase by hand, as many times as
their entry below says.

None of this is applied as a migration and none of it is part of the new
database build path: on a fresh database, over an empty `playlist_tracks`
table, running a file here does nothing. A file here is never run from an
agent session.
